# lfsr128sum

Высокопроизводительная C++20 библиотека и консольная утилита для вычисления 128-битных контрольных сумм на базе парных LFSR-генераторов (Linear Feedback Shift Register). Проект сочетает классическую математику регистров сдвига с современными SIMD-инструкциями и защищенной от изменений архитектурой версионирования.

## 🚀 Ключевые особенности

*   **Высокая производительность**: Скорость обработки данных в RAM достигает **450 МБ/с** на одно ядро благодаря двойной буферизации на семафорах C++20, многопоточному разделению логики (Producer/Consumer) и SIMD-инструкциям (SSE/AVX2).
*   **Встроенное версионирование хэшей**: Вывод утилиты защищен префиксами Modular Crypt Format (например, `$lfsr128$v1$`). Это гарантирует 100% обратную совместимость программы при обновлении внутренних полиномов, солей или масок смешивания байт в будущих версиях.
*   **Умная проверка целостности (`--check`)**: Встроенный валидатор файлов устойчив к Windows-специфике кодировок (автоматически обрабатывает маркеры UTF-8 BOM, срезает невидимые символы возврата каретки `\r` и не зависит от количества пробелов-разделителей).
*   **Множественная обработка и автономная запись**: Поддерживается передача пачки файлов за один вызов, а флаг `-o` позволяет утилите писать отчет напрямую на диск в обход кодировочных искажений терминалов (вроде UTF-16 LE в PowerShell).
*   **Total Progress Bar**: При обработке множества файлов утилита выводит единую сглаженную шкалу прогресса с динамическим расчетом средней скорости (EMA) и общего времени до окончания (ETA).
*   **Автономная сборка для Windows**: Конфигурация CMake автоматически настраивает статическую линковку библиотек рантайма (`libc++`, `libunwind`), что позволяет исполняемому файлу работать на любой «голой» Windows без предустановленного Qt Creator или компиляторов.

## 🛡 Алгебраическая архитектура (Multi-Field Mixing)

В отличие от стандартных контрольных сумм (например, CRC32), работающих в одном поле \(GF(2^n)\), алгоритм `lfsr128sum` построен на «столкновении» трех различных алгебраических структур:

1.  **Поле GF(251⁴)**: Арифметика полиномов над простым модулем 251.
2.  **Поле GF(241⁴)**: Арифметика полиномов над простым модулем 241.
3.  **Операция XOR**: Смешивание состояний, выходящее за рамки обоих полей.

## 🛡️ Анализ криптографической стойкости

Архитектура системы основана на четырех независимых генераторах состояний, объединенных операцией XOR. Выбор параметров минимизирует математический резонанс и максимизирует итоговый период хеширования.

### 1. Параметры генераторов
Система использует два простых основания p ≈ 2⁸ и взаимно простые степени \(n \in \{3, 4\}\):
*   **Группа A:** p₁ = 251, периоды \(T_{A1} = 251^4 - 1\), \(T_{A2} = 251^3 - 1\)
*   **Группа B:** p₂ = 241, периоды \(T_{B1} = 241^4 - 1\), \(T_{B2} = 241^3 - 1\)

### 2. Математическое обоснование периода
Общий период системы \(T_{total}\) вычисляется как наименьшее общее кратное (lcm) всех четырех периодов:

\[T = \text{lcm}(\text{lcm}(251^4-1, 251^3-1), \text{lcm}(241^4-1, 241^3-1))\]
\[T \approx 6.86 \times 10^{25} \gtrsim 2^{85.8}\]

**Почему это эффективно:**
*   **Взаимная простота степеней (3 и 4):** Поскольку gcd(3, 4) = 1, полиномы x³-1 и x⁴-1 имеют минимальное пересечение — только через общий множитель (x-1). Если бы использовались степени 2 и 4, период сократился бы в x²-1 раз (для 251 это потеря в ≈ 63 000 раз).
*   **Простые основания (241 и 251):** Использование разных простых чисел гарантирует, что специфические множители периодов (такие как 31501 and 29041) не пересекаются, что обеспечивает мультипликативный рост итогового цикла.

### 3. Стойкость к коллизиям
С суммарным периодом ≈ 2⁸⁶, пространство состояний хеш-функции превосходит стойкость классических 64-битных алгоритмов. Динамическая соль, зависящая от длины сообщения L, гарантирует уникальность траектории генераторов даже при идентичном начале данных.

## 🛠 Сборка проекта

Проект самодостаточен и не требует внешних зависимостей. На Windows поддерживается автоматическое развертывание статического рантайма под LLVM-MinGW (Clang) и MSVC.

```bash
# Клонирование репозитория
git clone https://github.com
cd lfsr128sum

# Конфигурация и сборка в режиме Release (критично для SIMD и многопоточности)
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

## 🖥 Использование консольной утилиты

```text
Использование:
  lfsr128sum <файл1> [файл2 ...] [опции]   Вычислить хэш одного или нескольких файлов
  lfsr128sum -c | --check <файл>            Проверить файлы по контрольным суммам

Опции:
  -o, --output <файл>     Записать результат напрямую в чистом UTF-8/ASCII формате
  --test                  Запустить тесты корректности, эквивалентности SIMD и покрытия
  --bench                 Запустить бенчмарк производительности алгоритма на ОЗУ
  --version               Вывести версию программы
```

### Примеры команд

*   **Вычисление хэша для одного файла:**
    ```bash
    ./lfsr128sum data.iso
    # Вывод: \$lfsr128v129f1d721b0514a4fdc6116219e24719e  data.iso
    ```

*   **Генерация файла контрольных сумм для группы файлов напрямую на диск:**
    ```bash
    ./lfsr128sum main.cpp lfsr_hash.h Makefile -o checksums.lfsr
    ```

*   **Проверка целостности файлов по проверочному списку:**
    ```bash
    ./lfsr128sum --check checksums.lfsr
    ```

## 📦 Использование как C++ библиотеки

Библиотека поддерживает **поточное хэширование** (Streaming Mode), что позволяет обрабатывать данные кусками любого объема, сохраняя внутреннюю цепочечную зависимость состояний регистров.

```cpp
#include "lfsr_hash.h"
#include "lfsr_file_hash.h"
#include "progress_bar.h"

// 1. Прямой расчет хэша файла без вывода шкал (удобно для фоновых проверок)
lfsr_hash::u128 file_hash = lfsr_hash::calculate_file_hash128("data.bin");

// 2. Расчет хэша с привязкой к общему ProgressBar
ProgressBar total_bar(1024 * 1024 * 100, "Processing Package");
lfsr_hash::u128 chunk_hash = lfsr_hash::calculate_file_hash128("chunk1.bin", total_bar, 0);

// 3. Низкоуровневое потоковое хэширование в памяти
lfsr_hash::gens generator;
generator.reset(); // Сброс в начальное состояние {1, 0...}

for (auto& memory_chunk : chunks) {
    // Состояние генератора сохраняется между вызовами g.process_input()
    lfsr_hash::u128 res = lfsr_hash::hash128(generator, memory_chunk);
    
    final_hash.first  ^= res.first;
    final_hash.second ^= res.second;
}

// 4. Математический откат состояния назад (для нужд реверс-инжиниринга)
generator.g_251x4.back_simd_block(last_processed_simd_block);
```
